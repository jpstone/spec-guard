# Spec Adherence Checklist

Use during implementation and review to prevent agent drift.

- [ ] Every changed file traces to the governing spec or an explicitly authorized deviation.
- [ ] No unrequested feature was added.
- [ ] No optional enhancement was implemented.
- [ ] No opportunistic refactor was included unless required by the spec.
- [ ] No dependency, framework, styling, or architecture change was made unless required by the spec.
- [ ] No TODO/commented placeholder was treated as implementation.
- [ ] No behavior was changed because it seemed "better" than the spec.
- [ ] No undocumented API/UI surface was created.
- [ ] Any spec conflict, gap, or ambiguity produced a blocker or spec deviation request.
- [ ] Any additive idea was recorded as follow-up, not implemented.
