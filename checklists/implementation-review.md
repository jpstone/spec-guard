# Implementation Review Checklist

Use before considering work complete.

- [ ] Implementation traces directly to the governing spec.
- [ ] Work classification did not change, or the change was acknowledged.
- [ ] Required tests were written before implementation.
- [ ] New tests were observed failing, or a concrete reason was recorded.
- [ ] Tests now pass.
- [ ] Tests validate behavior/contracts/user-visible outcomes, not prose.
- [ ] Unit tests target documented/exported API surfaces only.
- [ ] No UI was invented without required inputs.
- [ ] No scope creep was silently absorbed.
- [ ] Durable documentation was updated only when a durable contract changed.
- [ ] Follow-up work is recorded separately.
