# Preflight Checklist

Use before touching implementation code.

- [ ] Governing spec is identified.
- [ ] Spec is sufficient to begin.
- [ ] Work classification is selected.
- [ ] Required contract/documentation is identified, if any.
- [ ] Test type is selected.
- [ ] Tests to write before implementation are named.
- [ ] Expected failing behavior is known.
- [ ] UI inputs are present if UI work is required.
- [ ] Blockers are documented before halting.
